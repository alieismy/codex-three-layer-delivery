# Proposal Review

## Dimensions

- Coverage of approved requirements and constraints
- Sufficiency and fairness of alternatives when a real choice exists
- Architecture boundaries, responsibilities, data and interface flows
- Performance, reliability, security, operability, maintainability, cost, and exit path
- Decision rationale, rejected alternatives, assumptions, and residual risks
- Appropriate high-level depth without drifting into implementation instructions

## Failure Hypotheses

- One preferred solution is presented as inevitable
- The recommendation depends on an unverified compatibility or capacity claim
- Operational or security complexity is displaced outside the stated scope
- Architecture terminology conflicts with the project glossary or approved decisions

## Evidence

Trace findings to requirements, feasibility evidence, architecture decisions, standards, or inspected current documentation.
