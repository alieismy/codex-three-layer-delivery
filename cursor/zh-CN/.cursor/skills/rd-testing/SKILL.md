# $rd-testing

设计和执行**单元测试与系统测试**，产出测试用例集和测试报告。

## 交付物

- 测试用例集（可执行代码或结构化文档）
- 测试执行报告
- 缺陷清单（如有）

## 测试金字塔设计

```
         /  E2E  \           ← 少量关键路径
        / Integration \      ← 模块间交互
       /   Unit Tests   \   ← 大量、快速、独立
```

| 层级 | 覆盖重点 | 数量比例 |
|------|---------|---------|
| 单元测试 | 单个函数/方法的逻辑正确性 | 70% |
| 集成测试 | 模块间交互、外部依赖集成 | 20% |
| E2E/系统测试 | 端到端业务流程 | 10% |

## 执行步骤

### 1. 测试范围确定

- 确认被测代码范围和关联的需求/设计文档
- 识别核心路径和高风险模块
- 确定测试层级分配

### 2. 单元测试设计

#### 正常路径
- 每个公开方法至少一个正常路径用例
- 覆盖主要业务逻辑分支

#### 边界条件系统化枚举
| 类别 | 检查点 |
|------|--------|
| 数值 | 0、1、-1、MAX、MIN、MAX+1、MIN-1 |
| 字符串 | 空串、单字符、超长、特殊字符、Unicode |
| 集合 | 空集、单元素、满容量、重复元素 |
| 时间 | 零时刻、跨日、跨时区、闰秒 |
| 状态 | 初始态、终态、无效转换 |
| 并发 | 单线程基线、多线程竞争 |

#### 异常/负面测试
- 无效输入（类型错误、格式错误、注入尝试）
- 资源不可用（网络超时、磁盘满、权限不足）
- 依赖故障（下游服务返回错误、超时、空响应）
- 并发冲突（同时写入、乐观锁冲突）

### 3. 集成测试设计

- 模块间接口调用的正确性
- 数据库操作的事务完整性
- 外部 API 调用的 mock/stub 策略
- 消息队列的生产/消费正确性

### 4. 系统测试设计

- 端到端业务流程覆盖（基于需求文档的验收标准）
- 跨模块数据流验证
- 错误恢复和降级场景
- 性能基线验证（可选）

### 5. 性能测试设计（按需）

| 类型 | 目标 |
|------|------|
| 基准测试 | 单操作延迟/吞吐基线 |
| 负载测试 | 预期峰值下的行为 |
| 压力测试 | 超出容量时的降级表现 |
| 耐久测试 | 长时间运行的资源泄漏检测 |

### 6. 测试执行与报告

- 执行全部测试用例，记录结果
- 失败用例附根因分析
- 输出结构化报告：通过/失败/跳过/阻塞

## 规范注入检查

执行前检查：
- `.cursor/rules/` 中的项目测试框架和运行方式
- 已有的测试目录结构和命名约定
- CI 中测试执行配置

## 工具使用

- **Context7**：查询测试框架 API 和最佳实践
- **Sequential Thinking**：复杂测试场景的逻辑推理
- **客户端内置浏览器能力 / Playwright CLI / Playwright MCP（按需）**：Web 应用的系统测试 / E2E 自动化测试执行；默认优先 CLI 或客户端内置浏览器能力

## 质量门禁

交付前核查：

- [ ] 单元测试覆盖所有公开接口
- [ ] 正常/异常/边界条件均有覆盖
- [ ] 每个测试有明确断言（非只打印）
- [ ] 测试独立、可重复、无环境依赖
- [ ] 失败用例有根因分析
- [ ] 测试报告结构化输出

## 不做

- 不写只打印不断言的"测试"
- 不写依赖外部状态的不可重复测试
- 不用 `@Ignore` / `skip` 掩盖失败测试
- 不为了提高覆盖率写无意义的 getter/setter 测试
