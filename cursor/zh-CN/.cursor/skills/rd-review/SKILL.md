# rd-review

执行独立、基于证据的文档评审，输出分级问题、可执行整改建议和可辩护的评审结论。

## 交付物

- 问题优先的结构化评审报告
- 评审结论：通过 / 有条件通过 / 不通过
- 可选的条款级或章节级修订表
- 明确的证据缺口和复审条件

## 选择一种评审模式

只读取与目标匹配的参考文件：

| 模式 | 目标 | 参考文件 |
|------|------|---------|
| 需求评审 | PRD / SRS / 需求文档 | [requirements-review.md](references/requirements-review.md) |
| 可研评审 | 可研报告 / 可行性分析 | [feasibility-review.md](references/feasibility-review.md) |
| 方案评审 | 技术方案 / 概要设计 / 建设方案 | [proposal-review.md](references/proposal-review.md) |
| 设计评审 | 详细设计 | [design-review.md](references/design-review.md) |
| 标准评审 | 标准 / 规范 / 指南 / 规范性条款 | [standards-review.md](references/standards-review.md) |

目标跨越多种模式时，确定一种主模式；只有次要章节会实质影响结论时才额外读取一个参考文件。

## 公共评审框架

### 1. 固定评审依据

- 明确目标文档、版本、范围、读者和预期决策
- 阅读适用的上游需求、决策、模板、标准和评审制度
- 从材料中核实可查事实，只向用户确认会阻塞结论的权限、意图或决策
- 保留已批准的文档意图，不在评审中静默改写方案

### 2. 双轴评审

- **对齐轴**：文档是否忠实满足上游意图、已批准决策和权威来源？
- **内在质量轴**：文档自身是否完整、一致、可行、可追踪、可理解、可验证？
- 两个轴分别报告，避免一个轴的优点掩盖另一个轴的失败

### 3. 检验失败假设

- 识别关键假设，并分类为已验证、合理但未验证、可疑或已被证据反驳
- 检验最强反例、失败路径、边界条件和证据缺口
- 只有能够说明位置、依据和影响时才报告问题，不为显得全面而制造问题

### 4. 按影响分级

| 级别 | 含义 |
|------|------|
| **Blocker** | 使决策依据失效，或在根本性返工前无法安全推进 |
| **Critical** | 会改变范围、正确性、安全、合规或可行性的重大缺陷，批准前必须解决 |
| **Major** | 不单独推翻核心决策，但应整改或由有权主体明确接受的重要问题 |
| **Minor** | 对决策或文档可用性影响有限的局部改进 |

每个问题必须包含：

- 位置
- 所属轴：对齐 / 内在质量 / 两者
- 问题和证据
- 影响和分级理由
- 具体整改或核验动作
- 已知负责人或目标日期；未知时标记为待指定或待确认

### 5. 形成评审结论

| 结论 | 条件 |
|------|------|
| **通过** | 没有未解决的 Blocker 或 Critical；其余问题不破坏预期决策，且已显式跟踪 |
| **有条件通过** | 没有 Blocker；未决问题边界明确，并有条件、核验动作、分配状态和复审触发条件 |
| **不通过** | 存在 Blocker，或未解决的 Critical 使决策依据实质不成立 |

项目或组织评审制度优先于本默认规则。不得使用通用问题数量阈值。

## 工具选择

- 外部检索前先检查目标文档和适用上游来源
- 标准、法律、政策、市场事实或当前技术行为会实质影响问题时，使用 `rd-research`
- 优先一手来源和已配置工具；参考架构只能作为示例，不能作为评审权威
- 权威证据不可访问时缩小结论，并标记为需要人工核实

## 质量门禁

- [ ] 主评审模式和评审依据明确
- [ ] 已评估对齐轴和内在质量轴
- [ ] 已检验关键假设、反例和失败路径
- [ ] 每个问题都有位置、证据、影响、分级理由和动作
- [ ] 先列问题，再列优点和支持性观察
- [ ] 结论来自未解决影响，而非问题数量或评审者偏好
- [ ] 外部结论已核实、引用或明确限定

## 不做

- 不在评审中重新设计文档，只提出边界明确的整改建议
- 不以评审者偏好推翻证据充分的决策
- 除非影响解释或可用性，不报告纯样式问题
- 不编造标准条款、证据、负责人、日期或文档状态
