# rd-review

开展独立、基于证据的评审，产出分级问题、可操作整改建议和可辩护结论。

## 交付物

- 问题优先的评审报告
- 批准、发布或复审结论及明确条件
- 可选的条款、主张或章节级修订表
- 证据缺口、未解决风险和核验动作

## 选择一种评审模式

只读取目标对象对应的参考文件：

| 可研 | 可研报告 / 可行性分析 | [feasibility-review.md](references/feasibility-review.md) |

## 通用评审框架

### 1. 固定评审依据

- 明确评审对象、版本、范围、受众、目标决策和评审权限
- 阅读适用的上游需求、决策、来源材料、模板、标准和评审规则
- 区分内容评审、文字校对、事实核查、合规检查和设计批准
- 从材料中核实可查事实，只询问会阻塞结论的权限或意图
- 保留已批准意图，并将有边界整改与重新设计或代写分开

**完成标准：** 问题分级前，确切的评审对象、版本、范围、模式、权限、上游依据和结论用语均已固定。

### 2. 在两个独立轴上评审

- **对齐/证据轴**：对象是否符合上游意图和权威证据？
- **内在质量/论证轴**：对象本身是否完整、一致、可行、逻辑有效、易理解且可验证？
- 使用模式参考文件细化两个轴；一个轴的优点不能掩盖另一个轴的失败

**完成标准：** 每个重要章节均在两个轴上完成评估，或明确标记某轴不适用；两个轴没有被合并处理。

### 3. 检验失败假设

- 将重大假设分类为已核实、合理但未核实、可疑或已被反驳
- 检验最强合理反例、失败路径、边界条件、替代解释和证据缺口
- 因果主张检查时间顺序、机制、混杂因素，以及证据是否只支持相关而非因果
- 只有能说明位置、依据和影响时才报告问题；不得为显得全面而制造问题

**完成标准：** 每项重大假设和中心结论均已接受最强合理反例、失败路径、边界条件或替代解释的检验。

### 4. 按影响分级

| 严重度 | 含义 |
|--------|------|
| **Blocker** | 使决策或发布依据失效，或不经根本返工就无法安全推进 |
| **Critical** | 可能实质改变范围、正确性、安全、合规、可行性或中心结论，必须解决 |
| **Major** | 应修正或明确接受的重大缺陷，但单独存在时不使核心结论失效 |
| **Minor** | 对决策、论证或文档可用性影响有限的局部改进 |

每项问题必须包含位置、评审轴、问题、证据、影响、分级理由、具体整改或核验动作，以及已知负责人/日期。

**完成标准：** 每个保留问题均可依据位置和证据复现，具有基于影响的分级理由，并给出有边界的整改或核验动作。

### 5. 形成结论

默认文档结论为**通过 / 有条件通过 / 不通过**。文章模式可使用**可发布 / 修改后可发布 / 不可发布**。两类结论均遵循：

- 存在未解决 Blocker 时不得批准或发布
- 未解决 Critical 通常要求不通过，或修改后重新批准
- 有条件通过必须包含有边界条件、核验动作、分配状态和复审触发器
- 项目规则优先于默认规则；不得使用通用问题数量阈值

**完成标准：** 结论来自未解决影响和证据限制；每项条件均有动作、分配状态和复审触发器。

## 工具选择

- 外部检索前先检查目标对象和适用上游来源
- 标准、法律、政策、源代码、当前技术行为、引语、时间线或公共事实会实质影响问题时使用 `rd-research`
- 优先一手来源，并用独立来源检验存在利益关系或争议的主张
- 权威证据不可访问时收窄问题和结论，不得填补空白
- 问题和证据摘录应隐藏密钥及非必要的个人或基础设施标识；评审者确需原始材料时保留受控来源指针

## 质量门禁

- [ ] 主模式、对象版本、范围、权限和结论用语明确
- [ ] 证据/对齐轴和内在质量/论证轴均已评估
- [ ] 已检验重大假设、反例、失败路径和替代解释
- [ ] 每项问题包含位置、依据、影响、分级理由和动作
- [ ] 问题在前，优点和支持性观察在后
- [ ] 结论来自未解决影响和证据限制，而非问题数量或评审偏好
- [ ] 事实、引语、日期、版本和外部主张已核实或明确限定
- [ ] 问题和证据摘录不含密钥或非必要敏感标识

## 不做

- 独立评审中不重新设计或重写整个对象，只提出有边界整改
- 不因评审者偏好或政治立场赞同与否推翻有充分依据的决策或论点
- 只有风格问题会实质影响含义、可信度、可访问性或可用性时才报告
- 不编造证据、来源、标准条款、引语、负责人、日期或文档状态
