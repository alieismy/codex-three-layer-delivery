# $rd-detailed-design

基于技术方案产出**实现级详细设计**——接口定义、数据模型、关键流程、错误处理、并发控制。

## 交付物

- 详细设计文档（接口 / 数据模型 / 流程 / 状态机）
- API 契约定义（OpenAPI / Protobuf / GraphQL Schema）
- 数据库 Schema 设计

## 执行步骤

### 1. 设计输入确认

- 确认已有技术方案或概要设计（`$rd-technical-writing` 产出）
- 提取已确定的：架构决策、技术栈选型、约束条件
- 识别设计范围边界：本次设计覆盖哪些模块/服务

### 2. 接口设计

- 定义模块间接口契约（入参、出参、错误码、幂等性要求）
- 内部接口与外部接口分别标注
- API 版本策略说明
- 接口变更的向后兼容性约束

### 3. 数据模型设计

- 实体关系图（ER Diagram），标注主键、外键、索引
- 字段级设计：类型、长度、约束、默认值、是否可空
- 数据生命周期：创建 → 更新 → 归档 → 删除
- 数据一致性策略：强一致 / 最终一致 / 补偿

### 4. 关键流程设计

- 核心业务流程的时序图或流程图
- 每个流程标注：正常路径、异常路径、超时处理
- 并发控制策略：锁类型、乐观/悲观、重试策略
- 幂等性设计：哪些操作必须幂等，如何保证

### 5. 状态机设计（如适用）

- 状态定义与合法转换
- 无效转换的处理策略
- 并发状态修改的冲突解决

### 6. 安全性设计

通用软件安全设计要点：

| 维度 | 设计内容 |
|------|---------|
| 身份认证 | 认证方式选型、多因素认证需求、Token 过期策略 |
| 授权控制 | 权限模型（RBAC/ABAC）、最小权限原则 |
| 输入校验 | 校验规则、白名单/黑名单策略、注入防护 |
| 数据保护 | 传输加密（TLS）、存储加密、日志脱敏 |
| 接口安全 | 速率限制、签名验证、CORS 策略 |
| 依赖安全 | 第三方库版本锁定、已知漏洞检查 |

### 7. 错误处理设计

- 错误分类：可恢复 / 不可恢复 / 需人工介入
- 错误码体系设计
- 错误传播策略：向上传播 / 本层处理 / 降级
- 监控与告警触发条件

## 规范注入检查

执行前检查：
- `.cursor/rules/` 中的项目编码规范和命名约定
- 已有的接口设计规范和 API 风格指南
- 数据库设计规范（命名、索引、分区策略）
- 已固化的架构决策

## MCP 工具使用

- **Context7**：查询框架/库的 API 设计最佳实践
- **Sequential Thinking**：复杂流程和状态机推理
- **DeepWiki**：参考开源项目的接口和数据模型设计

## 质量门禁

交付前核查：

- [ ] 接口契约完整（入参/出参/错误码/幂等性）
- [ ] 数据模型无三范式以上的反范式未说明理由
- [ ] 关键流程覆盖正常/异常/超时路径
- [ ] 并发和幂等需求已处理
- [ ] 安全性维度已覆盖（至少：认证、授权、输入校验、数据保护）
- [ ] 错误处理策略明确
- [ ] 设计可追溯到需求（每个模块可关联到需求项）

## 不做

- 不跳过技术方案直接做详细设计（无上游输入时应先提示）
- 不留"待定"而不标注 owner 和截止时间
- 不设计不会用到的抽象层
