# B2 — 两个合理的评审材料准备接口

SYNTHETIC（合成）设计决策案例。两个候选都不是本仓库已实施改动；数字仅属于此合成案例，不是实测产品结果。

## R1 — 已批准范围和不变量

任务准备文档评审材料，不执行批准或发布。材料必须共同保留制品 revision、适用需求 revision、评审范围及证据实际读取边界。缺失的必需证据须对评审人可见。现有公共回执字段和责任人审批权限固定。下一决策是可逆的本地原型比较，不是生产采用。

目前有两个由同一组件维护的调用方；预计可能增加五个由独立团队负责的调用方，但尚未批准或排期。当前组合通过了四个人工编写的正常路径演练；未演练并发需求替换或必需附件不可读。

## 候选 P — 具名准备操作

`ReviewPacket.prepare(artifactId, reviewScope)` 解析适用 revision，读取范围内证据，返回包含这些身份和实际读取结果的材料。服务负责组装一致的快照；调用方获得材料或明确的证据不完整结果。草稿估计实现为130行、一个公共模块。没有原型验证快照语义、失败可见性或集成成本；设计仍需决定如何检测并发变化。它不决定责任人批准。

## 候选 C — 显式组合

当前调用方组合 `ArtifactStore.read`、`RequirementStore.read`、`EvidenceReader.load`、`PacketFormatter.build`，各边界及读取结果可见。调用方须保留全部返回的 revision 身份，应用正确范围，并在可能并发变化时于读取后再次比对。现有公共调用点已为两个既有调用方执行该序列。草稿估计实现为70行、四个模块。尚无独立团队调用方使用它，公共说明没有规定必需的顺序和再次检查规则。它不决定责任人批准。

## M1 — 本次设计工作

准备帮助责任人选择下一原型的最小接口比较，包括调用方必须知道的契约、已有证据、未决语义，以及有边界的比较计划。两种候选均可选择；本次请求不批准新架构。
