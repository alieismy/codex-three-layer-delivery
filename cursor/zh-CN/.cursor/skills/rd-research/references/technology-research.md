# 技术与开源研究

适用于仓库、库、协议、AI 模型或产品、AI Coding 工具和技术采用比较。

## 必查项

- 明确对象的产品形态、仓库、分支/Tag/Commit、版本、许可、平台、认证方式和订阅层级
- 检查官方文档和源代码/发布历史；Issue 和 Discussion 只能证明有人报告过行为，不能证明所有环境均受影响
- 区分宣传能力、文档能力、源码实现、已复现行为和生产适用性
- 评估架构适配、集成边界、互操作性、数据流、安全、隐私、供应链、性能证据、可维护性、支持和退出路径
- AI 系统应区分模型能力、宿主产品能力、工具可用性、账户权益、Prompt 行为和端到端系统性能
- 按显式决策标准比较候选方案，适用时包含现状基线

## 可复现记录

任何测试结论都应记录环境、版本、配置、数据集或 Prompt、步骤、预期结果、观察结果和限制。没有运行测试时，标注结论来自文档。

## 失败模式

- 用 Star、下载量、近期 Commit 或基准排名代替适用性证明
- 不检查约束和版本背景，直接复述 README 或厂商声明
- 将模型演示泛化为应用、工作流或生产保证
- 不分析威胁边界、平台和回退方案，直接复制社区配置
