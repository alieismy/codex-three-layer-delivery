# Cursor 中文提示词模板

在 Cursor Agent chat 中使用这些短模板。将 `{花括号}` 替换为实际项目信息。

根目录 `zh-CN/PROMPTS.md` 提供完整模板。本文件提供 Cursor `.cursor/skills/rd-*` 文档交付 Skill 的短模板。编码开发、代码评审、测试执行、部署执行不在本项目范围内。

## 需求分析

```text
使用 $rd-requirement

将以下原始需求结构化为可验证 PRD。

用户原始需求：
{粘贴用户原始表述}

已知约束：
- 干系人：{角色}
- 业务 / 政策约束：{约束}
- 系统 / 技术约束：{约束或待定}
- 时间 / 预算：{约束}
```

## 研究证据

```text
使用 $rd-research

请为以下事项收集并核验证据：
{决策问题、文档章节、标准条款、技术选型、政策问题或评审结论}

下游用途：
{rd-feasibility / rd-solution / rd-specification / rd-design / rd-review}

期望产出：
来源表，包含权威性、日期/版本背景、相关性、置信度、冲突、缺口和可引用笔记。
```

## 可行性分析

```text
使用 $rd-feasibility

评估 {项目 / 方案 / 功能} 是否可行。

决策问题：
{需要判断什么}

输入：
{PRD、会议纪要、政策、既有系统文档或粘贴上下文}

请比较可行候选方案，并区分事实、假设、估算和未知项。
```

## 技术方案

```text
使用 $rd-solution

为以下对象编写技术方案 / 概要设计：
{系统或项目}

需求来源：
{文件路径或摘要}

可研输入：
{文件路径或结论，如有}

约束：
- 既有系统：{边界}
- 安全 / 合规：{要求}
- 性能 / 容量：{目标}

请比较候选方案并给出推荐。
```

## 详细设计

```text
使用 $rd-design

为以下对象创建设计：
{模块、子系统、接口、数据域或流程}

包含模块边界、接口、数据模型、关键流程、错误、安全、审计、并发和未决决策。
```

## 标准规范

```text
使用 $rd-specification

起草 / 修订 / 评审以下标准或规范条款：
{粘贴条款或引用文件路径}

要求：
- 每条问题引用或定位具体条款
- 不编造标准依据
- 依据不足时标注需人工核实
- 可行时提供替换性规范文本
```

## 文档评审

```text
使用 $rd-review，{需求评审 / 可研评审 / 方案评审 / 设计评审 / 标准评审} 模式

评审对象：
{文档名称、版本或文件路径}

评审重点：
- {重点 1}
- {重点 2}

先输出分级问题，包含依据、影响和具体修改建议。
```
