The intended reader is the current adoption decision-maker, who works across system design, architecture, requirements, research, standards, and technical writing. The decision is which transferable methods deserve use in those activities, not whether to import seven upstream frameworks. The [repository's users and deliverables](../README.md#who-this-is-for) and [nine independent responsibilities](../README.md#skill-reference-eight-specialists-and-one-explicit-orchestrator) control this scope.

Three options are real: retain the current methods; try one concrete method in a bounded professional deliverable; or expand all nine Skill instructions now. The second has a reversible path and can reveal useful refinements without assuming a general deficiency. Retaining current methods avoids new work but leaves the candidate's value unknown. Expanding every Skill now would duplicate existing principles before establishing professional benefit. These are decision judgments, not measured cost claims.

The strongest objection to another trial is that existing instructions are already substantial and earlier baselines satisfied every selected assertion. A further reading step costs model or human effort and can produce invalid requests for more detail. Its value must be a better decision or usable handoff, not extra text, questions, findings, or a higher number of method names.

## Real requirement follow-up, 2026-10-05

The user requested one verifiable requirement from the README and actual behavior of a local manual-attribution tool. The delivered artifact contains one requirement and five acceptance rows. The planned comparison supplied the same sources and current Chinese `rd-requirement` instructions to two first attempts. The candidate added source-grounded normal, counterexample, and boundary scenarios for a material ambiguity. Each call reached its 240.027-second timeout without a completed requirement; neither reported turn usage. Both failures and partial messages remain in the original record. Unknown token usage is not zero. The timeouts do not establish method quality or their own cause. The main agent independently wrote the delivered requirement, and a separate read-only reviewer checked its sources without consulting the candidate method or attempted responder outputs.

The review found two Minor acceptance ambiguities. First, a fixed `N=300` scoring fixture could not be used directly as the page criterion: the actual generator chooses distinct target counts from 292 through 332. Page acceptance now reads each actual `N_i`, derives `L_i = max(80, ceil(0.55 * N_i))`, and tests the threshold and one item below it. Second, per-response diagnostics and evidence obligations needed an explicit success-path scope: when every response is invalid, the observed contract is an error and a hidden result area, with probability/calibration fields not applicable. Both findings were repaired, and the focused document rereview passed with no remaining finding in that scope.

A proposed explanation of uniform prior and the absence of identity proof was initially recorded as an implementation gap. After user authorization, one paragraph in each of the local and static result pages was updated. The recorded local checks then exercised three, one, and two accepted responses, the exact threshold, rejection below it, and browser recovery with the explanation visible. Scoring, thresholds, calibration, and data stayed unchanged.
