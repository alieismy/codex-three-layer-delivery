# rd-research

产出下游文档和评审可审计的**可追踪、面向决策的证据包**。

## 交付物

- 研究问题、决策依赖、范围和停止条件
- 使用外部检索时的检索策略和查询记录
- 包含权威性、日期/版本、适用性和置信度的主张—证据矩阵
- 关键发现、冲突、缺口、假设和证伪性证据
- 可引用笔记及建议的下游交接方向

## 选择研究模式

只读取目标任务需要的参考文件：

| 模式 | 适用对象 | 参考文件 |
|------|----------|----------|
| 证据支撑 | 为其他 `rd-*` Skill 核实法律、标准、论文、厂商事实、成本或市场证据 | 使用下方通用流程 |
| 技术与开源研究 | 仓库、库、AI Coding 工具、LLM 产品、协议、可维护性或采用比较 | [technology-research.md](references/technology-research.md) |
| 配置与基础设施研究 | Windows/Linux、VPN、VPS、代理、网络、安全、安装或配置行为 | [configuration-research.md](references/configuration-research.md) |
| 事实核查与论证证据 | 技术文章、时政文章、时间线、引语、因果或定量主张 | [fact-check-research.md](references/fact-check-research.md) |

目标跨越多个模式时，选择一个主模式；只有次要问题会实质影响结论时才再加载一个参考文件。

## 通用流程

### 1. 界定研究问题

- 说明结果支撑哪个决策或文档章节
- 将宽泛主题拆分为可回答的主张或研究问题
- 记录范围、法域、相关日期/版本、所需精度和停止条件
- 将需要检索的事实与需要用户或干系人授权的决策分开
- 判断证据支撑 `rd-requirement`、`rd-feasibility`、`rd-solution`、`rd-design`、`rd-specification`、`rd-writing` 还是 `rd-review`

**完成标准：** 每个研究问题均能在明确范围和停止条件内回答，且需要用户授权的决策已与可检索事实分离。

### 2. 使用来源层级

优先采用最接近主张责任主体的来源：

1. 用户提供的目标材料、系统观察、日志、源代码和权威项目记录
2. 有约束力的法律法规、标准、官方政策、当事方材料或原始数据集
3. 官方产品、厂商、框架、协议、API 和仓库文档
4. 原始论文、技术报告、Issue/Commit/Release 历史和标准化组织资料
5. 用于补充背景和交叉核验的高质量独立工程分析或报道
6. 明确标注的专家推断，且不得替代缺失证据

论坛、社交媒体、搜索摘要、AI 生成内容和聚合内容可提供线索，但不能单独证明重大结论。

**完成标准：** 每项重大主张均已确定足够权威、尽可能接近主张责任主体的来源类型；使用较低层级来源替代时已明确说明并给出理由。

### 3. 检索并检查

- 广泛技术检索优先使用英文关键词，最终按用户要求的语言呈现
- 引用前检查相关来源正文；不得把搜索结果或摘要当作已经核实的底层主张
- 易变事实记录检索日期；重要时记录准确版本、版次、Commit、法域或环境
- 高影响主张寻求独立交叉验证，并主动检索反证
- 材料不可访问或需付费时，只报告已核实元数据，并标记不可得内容
- 命令、输出、截图和摘录进入证据包前，应隐藏密钥及非必要的个人或基础设施标识，同时保留来源锚点和复现边界

**完成标准：** 每个被引用来源均已按主张所需深度检查；易变背景、重大反证和访问限制均已记录。

### 4. 评价证据

从权威性、时效性、直接性、独立性、适用性、可复现性和利益冲突评价每项重大来源。将每个结论映射到证据，并标注为事实、估算、推断、判断或未知。

**完成标准：** 每项重大结论均有证据强度和主张类型标记，并保留来源冲突与适用性限制。

### 5. 综合与交接

- 直接回答每个研究问题并说明证据强度
- 保留来源分歧；有充分依据时解释为何某一来源优先
- 区分观察到的行为、文档声明的行为和推荐判断
- 列出证据缺口、核验动作以及哪些新证据会改变结论
- 多阶段工作应在仓库既有位置维护一份权威证据包，并链接支撑笔记，不得把最终主张散落在多个临时文件中
- 原始笔记与发布级文本分离；最终叙事使用 `rd-writing`，独立结论使用 `rd-review`
- 只引用或保留支撑主张所需的有效片段；敏感或大体量原始输出使用受控指针，不复制到交接材料

**完成标准：** 每个研究问题均有边界明确的答案、证据链接、置信度或限制；重要时还包含证伪条件或后续动作，并有唯一可识别的下游交接方向。

## 工具选择

- 使用能到达来源所有者的最窄已配置能力：本地检查、官方文档检索、仓库工具、当前 Web 搜索或浏览器/PDF 检查
- 当前库、框架、SDK 和 API 文档使用 Context7 或同类工具；产品、政策、价格和时事主张应由其权威来源核实
- 仓库工具只证明已检查仓库中的事实；README 声明不能证明运行行为
- 使用模型原生推理综合证据；可选推理工具不能替代证据
- 能力不可用时记录限制，只在剩余证据边界内继续

## 质量门禁

- [ ] 范围、决策依赖、模式和停止条件明确
- [ ] 每项重大主张映射到已检查证据，或已标注未核实
- [ ] 易变事实包含必要的日期/版本/环境背景
- [ ] 已区分一手与独立来源，并保留来源冲突
- [ ] 高影响主张已主动检验反证和替代解释
- [ ] 可复现性限制、不可访问证据和后续动作明确
- [ ] 证据摘录和交接内容不含密钥及非必要敏感标识
- [ ] 多阶段工作只有一份可识别的权威证据包，不存在相互竞争的摘要
- [ ] 未编造引用、引语、条款、日期、版本、指标或行为

## 不做

- 不把 `rd-research` 作为所有任务的强制前置步骤
- 不把热度、仓库活跃、演示或厂商声明当作适用性证明
- 除非用户明确要求，不产出最终 PRD、可研、设计、标准、文章或独立批准结论
- 不执行未经授权的访问、破坏性测试、部署或生产变更
