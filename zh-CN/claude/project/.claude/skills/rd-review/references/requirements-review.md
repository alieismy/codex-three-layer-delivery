# 需求评审

## 评审维度

- 完整性：范围内场景、功能需求、非功能需求、约束、假设和排除项
- 可验证性：每项需求的验收方法和证据
- 一致性：术语、优先级、依赖和矛盾
- 边界清晰度：参与者、接口、数据、外部系统和排除项
- 用户意图：需求表达需要和结果，而不是强加的实现方式
- 可行性信号：高风险或未验证需求已标记，而非静默接受

## 失败假设

- 用户给出的解决方案被伪装成用户需求
- 核心场景、异常路径或非功能约束缺失
- 阈值或优先级没有来源或决策主体
- 验收标准只检查文字，不检查预期结果

## 证据

每个重大问题应追踪到原始诉求、会议记录、政策、干系人决策或已批准上游来源。
