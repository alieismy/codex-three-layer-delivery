# rd-writing

将已核实材料转化为面向受众的专业文档，同时保持主张、逻辑和证据可审计。

## 交付物

- 技术文章、解释性文章或技术白皮书
- 研究综述或事实核查报告
- 决策简报、立场文件或证据导向的建议备忘录
- 重要时附主张—来源映射和未解决证据说明

## 选择输出模式

只读取目标任务需要的参考文件：

| 模式 | 目标对象 | 参考文件 |
|------|----------|----------|
| 技术文章 | 技术文章、解释性文章、技术白皮书 | [technical-article.md](references/technical-article.md) |
| 证据报告 | 研究综述、事实核查报告、证据评述 | [evidence-report.md](references/evidence-report.md) |
| 决策简报 | 决策备忘录、立场文件、高管技术简报 | [decision-brief.md](references/decision-brief.md) |

## 通用流程

### 1. 固定写作契约

- 确认受众、决策或发布目的、范围、体裁、篇幅、语气、日期边界和引用格式
- 识别已提供来源、需要当前核实的主张，以及编辑或组织约束
- 保留既有术语、名称、日期、引语、编号和追踪关系
- 用户给出期望结论时，将其视为待检验命题，而非需要维护的事实

**完成标准：** 受众、目的、范围、模式、日期边界、来源集合、语气、篇幅和引用契约均已明确。

### 2. 建立主张结构

- 明确中心问题和候选结论
- 建立主张层级：中心主张、支持主张、证据、反方主张、限制和含义
- 区分事实、估算、推断、预测、观点和价值判断
- 删除与文档目的无关或缺乏证据的主张

**完成标准：** 每个保留主张均服务于文档目的，具有主张类型，并映射到证据、推理、反方主张、限制或明确的核验缺口。

### 3. 先核实再起草

- 先检查用户提供材料和项目来源；易变、争议、外部或影响决策的主张使用 `rd-research`
- 重要时核实时间线、版本、法域、单位、分母、引语上下文和来源所有者
- 记录冲突和证据缺口；不得让流畅文字掩盖不确定性

**完成标准：** 每项影响决策或拟发布的事实主张在起草正文前，均已按所需精度核实，或在计划措辞中明确限定。

### 4. 面向受众起草

- 除非体裁另有要求，先给答案或决策意义
- 使用最小充分结构，只在受众知识需要时解释专业术语
- 公平呈现最强重大反方论证，再进行回应
- 证据就近支持主张，并区分来源事实与作者分析
- 只有真实比较才使用表格，只有结构、流程或因果需要澄清时才使用图示

**完成标准：** 草稿面向目标受众回答中心问题，保留证据边界和反方论证，且不存在没有决策或解释用途的章节。

### 5. 编辑与核验

- 检查事实准确性、引用支持关系、时间顺序、因果逻辑、内部一致性、术语和数值单位
- 删除宣传式、口号式、模板式、重复和无依据表述
- 确认结论不超出证据，且局限具体而非套话
- 高影响或争议文档只维护一份权威的主张—来源映射
- 发布级正文、引语、截图和附录应移除密钥及非必要的个人或基础设施标识，同时保留重要证据限制

**完成标准：** 每项重要主张、引用、数字、引语、术语和结论均通过最终准确性与支持关系检查，未决限制仍保持可见。

## 工具选择

- 外部检索前先检查本地文档和仓库材料
- 使用 `rd-research` 建立或更新证据包，不在起草过程中重复深度研究流程
- 内容稳定后，使用文档格式 Skill 生成 `.docx`、PDF、演示文稿或表格产物
- 只有事实和论证完整后才使用语言润色 Skill

## 质量门禁

- [ ] 受众、目的、范围、模式和日期边界明确
- [ ] 中心与支持主张有证据支撑，逻辑连接成立
- [ ] 事实、推断、估算、预测、观点和示例可区分
- [ ] 公平呈现最强反方论证和重大限制
- [ ] 引用支持相邻主张，易变事实带有时间/版本背景
- [ ] 语气专业具体，无宣传或模板填充
- [ ] 最终结论未超出证据边界
- [ ] 发布内容不含密钥或非必要敏感标识

## 不做

- 实际目标为结构化交付物时，使用 `rd-requirement`、`rd-solution`、`rd-design` 或 `rd-specification`
- 主要任务是对现有文档给出独立结论时，使用 `rd-review`
- 不编造来源、引语、数据、被描述为真实的示例、日期或因果确定性
- 不通过隐瞒反证、不确定性或利益冲突来增强说服力
