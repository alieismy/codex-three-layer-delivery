# 面向前瞻决策的 RD 建议改进

日期：2026-10-05。状态：已实施并完成本地检查，纳入 `v1.8.1` 发布范围。仓库基线：`63b0a458eda42cd8f726c217c37ed2bcd38d7a3d`。本记录保留发布前的实现与行为证据，发布门禁结果在 Release 说明中另行报告。

## 决策与范围

共享指令现已要求：当真实机会、未来演进以及沿用现状的机会成本会影响本次决策时，应将其纳入分析。推荐强度与决策阶段匹配，区分探索、有边界的试点、扩大采用和生产承诺。证据足以支持可逆试点时，可以明确推荐试点，同时保留尚未满足的生产条件。

本次变更落实已批准的决策偏好。下方有界比较不能证明旧指令系统性压制创新，也不能证明新措辞提高了一般模型表现。对熟悉路径和新颖路径均按证据、约束、价值和授权判断。

| 范围 | 改动 |
|---|---|
| 全局行为和项目完成规则 | 增加结合场景寻找机会、匹配阶段的推荐、可调整的流程覆盖，以及有边界的子代理任务约定。保留强制顺序、完成标准、来源核验和授权边界。 |
| `rd-feasibility` | 比较机会成本和学习价值，识别相关决策阶段，为有依据的试验说明资源、成功、停止、恢复和扩大采用条件。 |
| `rd-solution` | 区分已批准约束与当前做法；考虑可信且实质不同的路径；分开目标架构、下一步推荐和当前授权范围。 |
| `rd-research` | 增加按条件触发的决策阶段与证据交接；技术模式把重要未知项转化为有界核验建议。 |
| `rd-review` | 只扩展可研和方案评审参考，检查阶段适配、机会成本和有潜力方案的证据。 |

其余五个 RD 工作流保持不变。本次工作未改变 Skill 描述、调用策略、公共模型默认值、Validator 逻辑或维护者 `AGENTS.md`；模型选择仍归配置管理。英文来源已同步至简体中文及适用的 Claude Code、Cursor 适配文件；Claude 项目适配器继续只作薄层导入。Cursor 保持一条常驻规则，其余专业规则按条件加载。

新增三个合成输出用例：有依据的试点、无依据的生产压力，以及固定接口约束下的有潜力架构。本次更新完成时，每个 canonical 语言目录有 47 个输出用例；该清单数量不同于下方选定的行为样本数。随后的[上游学习试点](upstream-learning-pilot.md)另行记录其新增案例与观察。

该方法与 OpenAI 强调意图、结果和必要约束、避免过度程序化控制的建议一致；官方指南提供设计依据，不能证明本次变更已产生效果。参见 [Rethinking skills and prompts for GPT-6 Astra](https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra) 和[当前模型提示指南](https://developers.openai.com/api/docs/guides/latest-model)。委派仍服从宿主实际能力和适用授权，相关能力边界参见[子代理文档](https://learn.chatgpt.com/docs/agent-configuration/subagents)。

## 给定文本比较

[证据记录](../../docs/evidence/forward-looking-rd-2026-10-05.json)保留冻结的指令、合成记录、Prompt、请求的模型设置、最终响应、哈希和断言判定。运行器使用 Codex CLI `0.160.0`，分别请求 Astra `max` 和 Sol 6.1 `high`，包含基线/候选两版、五个场景，每个组合运行一次。输入与断言在采样前冻结，基线/候选顺序交错平衡，每次调用超时为 240 秒。主比较保留每个组合的首次响应，下方单列的诊断没有替换这些结果；未向作答模型提供断言。

| 请求设置 | 版本 | 通过 | 部分通过／有歧义 | 失败 |
|---|---|---:|---:|---:|
| `gpt-6-astra` / `max` | 基线 | 21 | 1 | 0 |
| `gpt-6-astra` / `max` | 候选 | 22 | 0 | 0 |
| `gpt-6.1-sol` / `high` | 基线 | 21 | 1 | 0 |
| `gpt-6.1-sol` / `high` | 候选 | 21 | 0 | 1 |

场景覆盖有依据的试点、固定接口下的有潜力处理架构、相互一致但违背原始证据的委派摘要、精确窄范围需求修改，以及过早作出生产承诺的压力。主代理逐项阅读全部完整响应，按冻结断言人工判定。独立 Sol 6.1 评审者还复评了委派和窄范围修改的八个响应，其两项有歧义的部分通过判定已保留。评分未盲测，其余十二个响应未独立复评。

较早的四响应诊断使用了内部不一致的 fixture：按给定实验室速率，200 个配对案例约需 60 人时，超过两人日资源上限。四个响应均指出了冲突。原结果保留在证据记录中，不计入修正后的比较。随后将 fixture 改为包含设置、比较、评分和恢复在内的 80 人时上限，并纳入独立指令评审修订，再冻结完整比较。初版清单其余 16 个组合从未执行。

20 个已完成主样本按保守口径报告：**88 项断言中，85 项通过、2 项部分通过／有歧义、1 项失败**。Sol 6.1 候选版在窄范围修改中漏掉原有 `# Query PRD` 标题。另行记录的一次相同输入复测完整保留了摘录，但不能抹去原失败或证明已修复。两份基线委派响应在严格解释“工作不重叠”时被评为部分通过，因为其中独立评审重新检查了技术主张；若按输出所有权理解并允许独立复核交叉，两项可以通过。该歧义不能证明真实委派缺陷，也不能用作候选版改善的证据。

试点、候选选型和生产压力场景在两版指令、两种模型下均满足断言。因此，这些证据支持在保留限制的前提下落实所要求的指令偏好，不能证明一般性改善或零回归。原有指令已经要求完整保留内容；没有因单次可变输出叠加重复保留规则，也未修改其余五个工作流。

最重要的限制是运行器直接提供英文指令文本。同一宿主此前的探针报告：隔离参数下仍可能继承个人全局指令；本次采样期间该文件哈希保持不变。未独立证实完整上下文隔离或后端模型身份。这些样本没有验证隐式 Skill 选择、原生子代理委派、中文 Prompt 行为、Claude/Cursor 加载、真实部署或生产验收；委派场景只要求编写任务包和综合判断。

## 评审与验证

初次独立文本评审发现三个范围问题：通用研究被限定到技术模式且交接过窄；方案阶段条件缺少对应输入；试点条件适用范围过宽。三项均已修正。随后独立的 Sol 6.1 复查确认关闭，未在八个英文源文件中发现新的实质缺陷。此前恢复原评审代理的两次尝试遇到模型容量错误；这是执行失败，不是评审结论。

仓库 `validate.ps1`、`test-validator.ps1` 的 **24/24** 个负向用例及 `git diff --check` 均通过。Skill Creator `quick_validate.py` 对四个相关 Skill 的两种 canonical 语言版本和本机中文副本共 **12 项检查**通过。另已核对镜像字节一致性、未改动的其他 Skill 正文和元数据、先前工作保留、UTF-8/LF、引用及公开数据卫生。本机受保护恢复脚本的 `-WhatIf` 检查通过，未实际恢复。该非发布实现阶段未运行联网 Release 门禁。

本机已安装副本另行同步并保留校验过的备份，个人路径和内容不进入本公开记录。已有模型配置保持不变。该实现阶段未进行 commit、push、tag 或 Release。后续若要证明决策质量提升，需要具有代表性的真实任务和结果证据，不能仅依赖这组小规模合成比较。
