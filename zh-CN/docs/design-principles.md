# 设计原则

## 交付物驱动

本体系把 agent 工作导向具体交付物：

- 需求文档；
- 技术方案；
- 详细设计；
- 实现 diff；
- 评审意见；
- 测试和测试报告；
- 部署操作手册。

## 最小必要改动

Agent 的工作范围应足够窄，确保每一行改动都能追溯到用户请求。

避免：

- 顺手重构；
- 无关格式化 churn（噪音变更）；
- 假设性抽象；
- 任务不需要的新依赖。

## 证据纪律

结论应由当前可获得的最强证据支撑：

1. 代码或实际系统行为；
2. 官方文档、标准或 RFC；
3. 论文或技术报告；
4. 工程实践文章；
5. 明确标注的推断。

## 安全默认值

公开模板应比个人本地配置更保守：

- 保守 sandbox 默认值；
- full access 需要显式选择；
- 不包含真实凭据；
- 不包含私有 relay endpoint；
- 不把未验证的模型或包版本作为默认事实。

## 周期性复核

用于弥补模型局限的规则，应在模型或工具大版本发布后复核。

表达项目固有工程纪律的规则应保持稳定，除非项目工作方式发生变化。
