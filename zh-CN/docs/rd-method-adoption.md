# 面向专业场景的 RD 方法采用

状态：场景映射、已授权的本地写作试验及后续真实需求案例完成，2026-10-05。Skill 指令保持不变。本文维护场景映射和采用决定。[写作证据](../../docs/evidence/rd-role-adoption-2026-10-05.json)保留确切初稿、读者响应、输入及评价；[需求跟进记录](../../docs/evidence/rd-requirement-real-pilot-2026-10-05.json)汇总经过来源核验的评审与本地功能证据。方法增量收益、真人及业务验收仍未验证。

## 当前决定

保留现有 Skill 指令，使用下方场景映射为专业任务选择具体方法。当前的方法采用决定提供了一项真实写作任务；代理读者能够找到建议动作、相关职责、下一步输入和证据边界，没有发现阻塞当前使用的补问。保留初稿与读者使用观察作为工作样例；本次结果不足以支持新增指令或回归用例。其他方法仍可在具备必要输入的代表性任务中试验。只要价值假设明确、试验可逆且范围可控，就不必先证明现有方法失败。

将后续真实需求案例保留为第二个工作样例。有来源的验收实例与单独评审解决了两处局部歧义，获授权的实现随后通过了记录中的本地功能检查。预定的两次对照调用均超时且未产出完整需求，因此不能用最终交付需求进行基线与候选方法的质量比较。在实例能够澄清实质歧义时，按现有工作流使用；保持现有指令，以及每个 canonical 语言目录的 51 个输出用例定义。

目标读者是当前采用决策者，其工作涉及系统设计、架构、需求、研究、标准与技术写作。要决定的是哪些方法值得用于这些工作，而不是是否引入七套上游框架。[仓库的用户与交付物](../README.md)及[九项独立职责](../../README.md#skill-reference-eight-specialists-and-one-explicit-orchestrator)控制本轮范围。

真实选项有三种：保留现有方法；在一个有边界的专业交付中试验一种具体做法；现在就扩写九个 Skill。第二种有可逆路径，能够探索有用的细化方式，无须假定当前存在普遍缺陷。保留现状可以避免新增工作，但候选价值仍然未知。直接扩写全部 Skills 则会在专业收益尚未建立时重复已有原则。这些是决策判断，不是实测成本结论。

最强反对意见是：现有指令已包含较多相关方法，前面实验的基线也通过了全部所选断言；再增加阅读步骤可能消耗模型或人工投入，并产生无效的补充细节要求。它的价值应体现为更好的决定或可继续使用的交付物，不能用更多文字、问题、发现或方法名称证明。

## 写作试点与采用决定

冻结计划使用当前中文 `rd-writing` 正文及决策简报参考文件形成初稿。新的代理读者随后只获得成稿和七项实际阅读任务。若经来源核验的反馈指出实质性解释问题，作者只修复这些问题，再由新的代理读者使用修订稿。确实尚待干系人决定的问题仍保留为未决项。若没有实质问题，则保留基线并省去无必要调用。

读者任务涉及建议动作、下一步输入和责任、三类相邻专业场景的材料需要、历史证据边界、最强反对意见、改变决定的条件，以及实际需要补问的位置。评价专业正确性、决策价值、下游可用性和总投入；标题、关键词数、更多问题或篇幅本身不计为收益。

计划只在实质性问题需要修订时才允许开展前后观察。本次执行止于一份初稿的代理阅读观察，没有形成修订前后收益或等算力对照。两份首答及其 CLI token/用时字段均已保留。读者任务及评价维度在采样前冻结；读者没有获得来源包或预期答案。

## 真实需求跟进（2026-10-05）

用户要求依据一个本地手动归因工具的 README 和实际行为，形成一条可验证需求。交付物包含一条需求和五项验收条件。用户随后授权修改结果说明并开展本地验收，保留现有阈值和校准算法，之后选择回到框架形成采用结论。正式产品基线、优先级和真人业务验收仍是独立决策。

计划中的对照为两次首答提供相同来源和当前中文 `rd-requirement` 指令；候选条件增加了针对实质歧义、具有来源的正常实例、反例和边界实例。两次调用均在 240.027 秒后超时，没有完整需求，也未报告 turn usage。原记录保留两次失败及局部消息；用量未知不等于零。超时不能证明方法质量，也不能自行解释超时原因。主代理独立编写了最终交付需求；另一个只读评审代理核对实际来源，没有查阅候选方法或受测代理输出。

评审发现两处 Minor 验收歧义。第一，固定 `N=300` 的评分夹具不能直接作为页面判据：实际生成器从 292 至 332 中选择不同的目标数量。页面验收现按每份实际 `N_i` 计算 `L_i = max(80, ceil(0.55 * N_i))`，构造等于门槛和少一项的输入。第二，逐份诊断及其证据义务需要明确限定为成功路径；全部回答无效时，已观察契约是报错并隐藏结果区，概率和校准字段不适用。两项问题均已修正，聚焦文档复核通过，该范围内没有遗留问题。

草稿提出的均匀先验和身份非证明说明，最初被记录为实现差距。获得用户授权后，本地页与静态页各修改了一段说明。随后记录的本地检查覆盖三份、一份和两份有效回答、等于门槛、少于门槛被拒，以及浏览器错误后恢复并显示说明。评分、阈值、校准和数据保持不变。

这些观察证明该需求案例及其获授权的本地功能跟进已经完成。测试没有使用真实模型输出或身份真值；归因准确率、性能、生产就绪和真人验收仍未验证。应用检查不衡量候选方法的贡献。两个对照条件均未完成，编写、评审、实现及人工总投入也未完整计量，因此方法增量收益仍未知。

采用决定是保留这个案例，在有来源的实例能够消除实质歧义时使用。现行 [`rd-requirement`](../skills/rd-requirement/SKILL.md#4-验收标准定义) 已要求正常、异常和边界覆盖，以及范围内的收敛检查。两项修订体现了该契约的应用，不足以支持向九个 Skill 追加相同规则，或要求每条需求都必须增加独立代理。未来仍可在价值假设和输入明确时开展有边界的试验；先检查执行入口能否完成。扩大采用需要有代表性的可用成果和可接受的总投入；若主张比较收益，还需保留输入可比的首答。现有基线先失败不是试用有价值方法的前提。
