# Requirements Review

## Dimensions

- Completeness: in-scope scenarios, FR, NFR, constraints, assumptions, exclusions
- Verifiability: acceptance method and evidence for each requirement
- Consistency: terminology, priorities, dependencies, and contradictions
- Boundary clarity: actors, interfaces, data, external systems, and exclusions
- User intent: requirements express needs and outcomes rather than an imposed implementation
- Feasibility signals: high-risk or unverified requirements are flagged, not silently accepted

## Failure Hypotheses

- A proposed solution has been disguised as a user requirement
- A core scenario, exception, or non-functional constraint is absent
- A threshold or priority has no source or decision owner
- Acceptance criteria test wording rather than the intended outcome

## Evidence

Trace each material finding to the original request, meeting record, policy, stakeholder decision, or approved upstream source.
